# Bug audit — 2026-10-18

Audited version 0.6.0, commit `45cd096`. This report records 14 confirmed defects. It does not claim that every possible defect has been discovered. Unsupported features listed in the roadmap are excluded.

The existing suites pass: **71 backend tests, 13 frontend tests, and 6 browser workflows**. Additional checks used temporary databases, captured public fixtures, controlled subprocess responses, and browser request interception. The user's saved database was not modified by these reproduction checks. Local services were started for browser inspection. No fresh upstream scientific observations are claimed.

P1 means a high-priority integrity defect. P2 means a functional or correctness defect requiring a fix. P3 means a lower-priority compatibility defect.

## Resolution in 0.6.1

All 14 findings below are fixed. The original reproductions are retained as the audit record.

- Findings 1, 2, 5, 6, 9, 10, 11, 12, and 13: backend coverage in `backend/tests/test_audit_fixes.py`.
- Findings 3 and 4: exact file-byte/hash and pre-execution assembly rejection tests in `backend/tests/test_snpeff_runner.py`.
- Findings 7, 8, and 14: browser regression workflows in `frontend/e2e/workflow.spec.ts`, plus guided-default and request-freshness unit tests.
- Record-list pagination and investigation-specific regression requests also have frontend tests.
- Final verification: 101 backend tests, 21 frontend tests, 9 browser workflows, and a production build. A real pinned local SnpEff run and portable replay also passed. Historical 0.5.0/0.6.0 verification and existing saved baselines remain supported.

## 1. P1 — Source-linked VEP snapshots can contradict their bundled source

Location: [bundle.py](D:/Creation/GenomeDebugger/backend/app/bundle.py:179).

Reproduction: create a bundle from a preserved VEP source and transcript comparison. Change the selected snapshot's consequence from its preserved `3_prime_UTR_variant` to `stop_gained`, retain its Ensembl tool/source provenance and transcript ID, recompute the ordinary investigation result, and update that entry's hash. `/api/bundles/verify` returns HTTP 200 with `valid: true`.

The verifier checks source IDs and hashes but does not reconstruct the source-generated snapshot annotation/variant rows from the preserved response. This is an internal contradiction, independent of whether the uploader is trusted. A verified portable record can therefore cite source evidence that does not support its annotation.

Fix: validate source-generated VEP snapshot fields and complete row collections against their selected source records; explicitly distinguish later user transformations.

## 2. P1 — Import silently keeps a conflicting SnpEff check with the same ID

Location: [storage.py](D:/Creation/GenomeDebugger/backend/app/storage.py:59), [main.py](D:/Creation/GenomeDebugger/backend/app/main.py:324).

Reproduction: import a valid bundle with SnpEff version `5.2`. Import another individually valid bundle using the same check ID, VCF, and timestamp but version `DIFFERENT-VERSION`, with its investigation summary updated consistently. Both imports return HTTP 200. The second investigation stores `DIFFERENT-VERSION`, while its linked saved check remains `5.2` because `INSERT OR IGNORE` discards the conflict. Exporting that investigation then creates a bundle which fails verification.

Fix: check immutable artifact conflicts before import and return an actionable conflict, or use complete content-derived identities. Apply the policy consistently to linked source and check tables.

## 3. P2 — Windows SnpEff input hash does not cover the file actually executed

Location: [snpeff_runner.py](D:/Creation/GenomeDebugger/backend/app/snpeff_runner.py:77).

The temporary VCF is written in text mode, which converts LF to CRLF on Windows. Execution provenance hashes the original LF string. Inspecting the actual temporary file inside a controlled subprocess call produced SHA-256 `001fa41bac1cb648ffc6c6f780b60f669260b15222579ea270658113de5932fe`, while the recorded value was `aefe70fa857b1fbc361536b9a4748a435d395ce0ba0a9a5cb3c7b17b1f5c8a7d`.

Fix: write explicit bytes or fixed newlines, and hash the exact bytes passed to the process.

## 4. P2 — Local SnpEff execution does not validate database assembly

Location: [snpeff_runner.py](D:/Creation/GenomeDebugger/backend/app/snpeff_runner.py:68), [setup_snpeff.py](D:/Creation/GenomeDebugger/scripts/setup_snpeff.py:49).

The installer permits arbitrary database names and the runner only verifies artifact hashes. It never checks whether the database belongs to the GRCh38 assembly used by the source query. A controlled manifest named `GRCh37.test` was accepted for a GRCh38 record, the subprocess was invoked, and a matching simulated ANN response yielded `agree`.

This check used simulated process output; it does not claim a real GRCh37 annotation agreed. It demonstrates that the assembly guard is absent before execution and comparison.

Fix: record and validate database assembly/reference metadata before executing a source record. Unsupported build combinations must be explicit.

## 5. P2 — Failed bundle import commits partial data

Location: [main.py](D:/Creation/GenomeDebugger/backend/app/main.py:320).

Each source, check, and investigation is saved in a separate transaction. Injecting a storage-full failure on the second write returned HTTP 507, but the first source record remained in the database. Failures later in the sequence can leave other incomplete combinations.

Fix: preflight all conflicts and capacity, then import the complete bundle in one transaction and roll it back on failure.

## 6. P2 — Deletion does not reliably recover storage capacity

Location: [storage.py](D:/Creation/GenomeDebugger/backend/app/storage.py:29), [storage.py](D:/Creation/GenomeDebugger/backend/app/storage.py:180).

The budget adds incoming serialized bytes to SQLite's physical file size. Deletion frees database pages without shrinking the file, but the guard does not count reusable pages. With the supported 10 MB test budget, five valid large investigations filled the available budget. After deleting all five, the approximately 9 MB file remained and inserting another investigation still failed, despite the available free pages.

Fix: account for reusable pages or provide deliberate compaction and a recovery path. Duplicate artifact imports should also avoid charging capacity for bytes that will not be inserted.

## 7. P2 — Editing during comparison hides result staleness

Location: [App.tsx](D:/Creation/GenomeDebugger/frontend/src/App.tsx:142).

Browser reproduction: submit the draft titled `Submitted version`, hold its response, edit the still-enabled JSON to `Edited during request`, then release the earlier response. The displayed result belongs to the submitted input, the draft retains the later edit, and the stale-input warning count is zero. `showResult` unconditionally clears the dirty flag.

Fix: compare the response input with the current draft, or track the submitted draft revision. Later edits must remain visibly unsaved.

## 8. P2 — Old public-source responses survive a changed query

Location: [PublicSourcePanel.tsx](D:/Creation/GenomeDebugger/frontend/src/PublicSourcePanel.tsx:62).

Browser reproduction: hold a lookup for position `6524705`, change the editable position to `999999`, then release the old response. The form shows `999999` while the loaded source and enabled comparison controls use `6524705`. Clearing the record on input change does not invalidate the request already in flight.

Fix: cancel or invalidate pending lookups when the query changes; accept a response only for the current query revision. Apply the same rule to related source checks.

## 9. P2 — Clinical assertion date changes disappear from differences

Location: [engine.py](D:/Creation/GenomeDebugger/backend/app/engine.py:168).

Two otherwise identical annotations with the same condition, framework, classification, and review status but dates `2023-01-01` and `2024-01-01` produce an empty differences list. The assertion date is modeled and asserted by regression checks but omitted from primary and additional annotation comparison.

Fix: include date changes with an explicit metadata/significance policy. A date change need not imply a changed classification.

## 10. P2 — Malformed bundle metadata causes HTTP 500

Location: [bundle.py](D:/Creation/GenomeDebugger/backend/app/bundle.py:137), [main.py](D:/Creation/GenomeDebugger/backend/app/main.py:306).

Setting a bundle's `engine_version` to an array causes an unhashable-type exception during set membership. `/api/bundles/verify` returns HTTP 500 instead of a validation response; import uses the same verifier. The handlers catch `ValueError` and `KeyError`, not this `TypeError`.

Fix: validate the manifest schema and types before operations such as set membership, and return structured errors for malformed bundles.

## 11. P2 — Contradictory SnpEff explanation passes replay verification

Location: [bundle.py](D:/Creation/GenomeDebugger/backend/app/bundle.py:80).

Replace an agreeing check's generated explanation with `Every matched transcript DISAGREES.`, update its entry hash, and verify the bundle. It passes because comparison replay validates status, matches, and unmatched rows but never compares the generated explanation. The UI displays this contradictory explanation.

Fix: verify every derived check output, or regenerate explanatory prose from the validated structured outcome when loading/importing.

## 12. P2 — Old pinned regression cases disappear from discovery after 100 cases

Location: [storage.py](D:/Creation/GenomeDebugger/backend/app/storage.py:212), [RegressionPanel.tsx](D:/Creation/GenomeDebugger/frontend/src/RegressionPanel.tsx:23).

Create an original pinned case, then 100 newer cases. Listing returns only 100 and omits the original. The frontend searches only this truncated global list to discover the current investigation's case, so older investigations can appear to have no baseline and offer to create another. The listing has no pagination or investigation filter.

Fix: fetch cases by source investigation or implement complete pagination. Other capped lists should expose navigation to older records as well.

## 13. P2 — Valid generated difference paths cannot receive significance overrides

Location: [models.py](D:/Creation/GenomeDebugger/backend/app/models.py:177).

Valid 100-character gene and transcript IDs produce a 236-character additional-annotation difference path. The same schema rejects that path in `meaningful_overrides`, which limits keys to 200 characters. Consequently, a valid displayed difference cannot be configured using the supported override mechanism.

Fix: align override identity/length constraints with all difference paths the engine can generate, preferably using a structured stable identifier.

## 14. P3 — Guided editor rejects valid defaulted input

Location: [GuidedInput.tsx](D:/Creation/GenomeDebugger/frontend/src/GuidedInput.tsx:53).

Omit `synthetic` from a valid non-synthetic input. The backend accepts it and defaults it to `false`. Importing the same JSON and opening Guided form instead displays `Investigation.synthetic must be true or false`. The frontend and backend disagree about an optional field.

Fix: apply documented defaults before guided validation, while preserving invalid explicit values for useful error reporting.

## Suggested repair order

1. Bundle/source consistency and immutable artifact conflicts.
2. Exact execution bytes and assembly validation.
3. Atomic import and storage recovery.
4. Browser request/draft freshness.
5. Comparison completeness, validation failures, regression discovery, and schema parity.

Add focused regression coverage for these reproductions. Existing passing suites do not cover these failure paths.
