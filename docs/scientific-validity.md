# Scientific validity and limitations — 0.6.0

## Verified behavior

- Input validation rejects invalid bases, unchanged alleles, malformed nested fields, duplicate row keys, and reference alleles that contradict supplied context. Guided input edits primary and additional variants and annotations.
- The pure comparison engine establishes local representation equivalence for equal-length substitution edits on identical declared assembly, accession, and supplied reference context. All length-changing edits, including complex replacements, remain unresolved using supplied context alone. This engine is not a full normalizer.
- An explicit independent NCBI check validates the complete submitted reference allele against pinned GRCh38.p14 primary nuclear RefSeq sequence, then compares contextual SPDI and captures genomic HGVS. Reference mismatch skips notation requests. Observations, URLs, hashes, and flags are reconstructed during bundle verification. The check stays separate from the immutable local-context result.
- The captured public example in `fixtures/ncbi-repeat-deletion-observation.json` was fetched live during 0.6.0 development: chr1:10004 CC>C and chr1:10005 CC>C both yielded `NC_000001.11:10003:CCC:CC` and `NC_000001.11:g.10006del`. Annotation placeholders make no consequence claim. Service behavior can change; replay uses saved responses.
- Additional variants match exact assembly/accession/position/ref/alt representations. Annotation matching uses tuples and escaped display paths; delimiter characters cannot collapse separate rows. Switching the primary transcript inside an unchanged full annotation set creates selection changes without false missing-row differences.
- Synthetic transcript replay holds allele, software, release, and configuration constant before attributing selection changes as verified within that supplied fixture. Demo gene/transcript/protein names are fabricated.
- Clinical classifications are compared only within matching condition IDs and frameworks. The app infers no clinical classification.
- Candidate regression checks assert absolute primary and additional outputs, including annotation and variant records. Shared changes in both snapshots fail; row order alone does not. Pinned replay compares output and evidence. Evidence drift is separately visible for candidate runs.
- Current Ensembl GRCh38 SNV retrieval validates query, reference base, and VEP response; captures release/assembly metadata, URLs, response hashes, and retrieval time. The chr1:6524705 C>T and rs56116432 chr9:133256042 C>A examples were checked live against Ensembl and the earlier independent NCBI SNV check. Representation agreement does not validate transcript predictions.
- Local SnpEff execution verifies observed Java, JAR, configuration, and transcript-database file hashes before and after running. It preserves input/output VCF, stderr, command, version, and artifact provenance. A live run of SnpEff 5.4c with `GRCh38.mane.1.0.ensembl` against the preserved chr1 example is in `fixtures/snpeff-mane-public-run.json`. Exact transcript versions did not match, so the comparison remains unresolved. User-supplied VCF remains supported with declared provenance.
- Historical VEP import preserves original JSON bytes and declared original time, software version, release, assembly accession, and source location. Comparisons may select two separately preserved outputs. Historical imports cannot satisfy current API cache lookups. Bundle verification reconstructs parsed observations from original artifacts.
- Portable bundles verify hashes, derive NCBI observations and flags again, and replay declared engine output. Current exports use versioned result IDs; originals remain unchanged. Archived 0.5.0 bundles use frozen 0.5.0 verification rules and remain visibly historical. Hashes detect corruption and contradiction; they do not authenticate uploader or source.

Unit, API, and browser tests cover malformed input, disagreement, offline behavior, tampering, and large bundle round trips.

## Unsupported claims and remaining scope

- Cross-assembly liftover, cross-sequence mapping, mitochondrial HGVS, VRS computation, general HGVS parsing, and symbolic/structural variants are unsupported. NCBI checking covers short A/C/G/T primary variants on pinned GRCh38.p14 primary nuclear sequences. Extra variant rows still match exact representations.
- NCBI contextualization is an observed service result. Preserved responses allow offline consistency checks; internal hashes are not signatures. User reference contexts and arbitrary provenance are not externally authenticated.
- A real second annotation run locates agreement or disagreement but does not establish why an earlier consequence changed. Transcript versions are never silently stripped. No verified biological causal explanation is claimed from a partial match.
- Current Ensembl cannot supply an earlier analysis. Its metadata and VEP calls are not atomic and VEP executable version is not reported. Imported historical metadata is declared. Output comparison reconstruction is supported; reproducing an old pipeline still needs its original executables, databases, configuration, and references.
- Bundled execution records preserve provenance but are not authenticated remote execution attestations. Supplied SnpEff versions or database hashes do not prove execution. The installer records observed SnpEff archive hashes; its latest-distribution URL is mutable.
- Regression runs rerun the local comparator. They do not automatically execute VEP, NCBI, or SnpEff. Explicit adapter and runner actions have their own preserved records.
- There is no ClinVar adapter, authenticated release timeline, patient-specific interpretation, pathogenicity prediction, or clinical review-status inference. More independently sourced cases and performance validation are needed before broader deployment.

GenomeDebugger is a research and bioinformatics quality-assurance tool, not a certified clinical diagnostic device.
