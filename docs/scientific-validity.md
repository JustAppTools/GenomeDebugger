# Scientific validity and limitations

## Validated in this release

- **Input consistency:** The schema rejects missing required fields, invalid bases, an unchanged allele, and a `ref` that does not match its supplied reference context. The context itself is user supplied and is not checked against a reference genome.
- **Narrow allele comparison:** On the same declared assembly, sequence accession, and identical supplied reference context, shared-prefix/suffix trimming identifies equivalent *nonempty substitution edits*. It is symmetric and idempotent in tests. This is local representation equivalence, not external sequence validation.
- **Local indel comparison without an identity claim:** The engine can show whether two edits produce the same sequence inside an identical user supplied context. Matching local sequences remain `unresolved` for biological identity because the context is not independently authenticated or repeat-normalized against a full assembly.
- **Additional variants and annotation rows:** Snapshots accept extra variants with per-variant annotation lists. Variants match only by exact assembly, accession, coordinate, `ref`, and `alt`; unmatched rows are explicit differences. Missing reference context or source verification remains visible as an identity limitation.
- **Controlled synthetic replay:** For one synthetic allele, a transcript lookup is deterministically rerun against each selected transcript. The engine requires matching observed outputs and identical tool/version, source/release, and configuration before calling transcript selection verified **within that supplied fixture**.
- **Clinical comparability guard:** Classifications are compared only when condition ID and framework match. No classification is inferred.
- **Traceability:** Field differences, candidate causes, and replay results carry evidence IDs. Canonicalized input JSON and lookup rows are SHA-256 hashed.
- **Regression assertions:** A pinned replay requires the saved annotations, identity status, field differences, findings, and hashed evidence data to match the current engine. A candidate replay requires the same submitted variant descriptions and compares expected output fields while surfacing input and evidence drift. A passing candidate run with changed evidence does not imply the evidence sources are equivalent.
- **Public SNV source checks:** The Ensembl adapter accepts only GRCh38 A/C/G/T single-base substitutions on named chromosomes. It checks the submitted `ref` against Ensembl's one-base reference sequence and verifies VEP's returned assembly, coordinate, and allele string. It preserves the raw VEP record, response SHA-256, source URLs, retrieval time, assembly accession, and the releases reported by `/info/data`. These are tested against mocked API responses. The [documented Ensembl VEP region example](https://rest.ensembl.org/documentation/info/vep_region_get) is the live smoke-test case.
- **Independent allele cross-check:** A pinned [NCBI GRCh38.p14 assembly report](https://ftp.ncbi.nlm.nih.gov/genomes/all/GCF/000/001/405/GCF_000001405.40_GRCh38.p14/GCF_000001405.40_GRCh38.p14_assembly_report.txt) maps each primary chromosome to a versioned RefSeq accession; its `=` relationship marks matching GenBank and RefSeq sequences. NCBI EFetch independently checks the reference base, then Variation Services checks contextual SPDI and genomic HGVS for that one-base substitution. We preserve all returned evidence, source URLs, hashes, and agreement status. The Ensembl public example at chr1:6,524,705 C→T and the VEP ID example rs56116432 at chr9:133,256,042 C→A both agreed with NCBI in live checks. The second Ensembl response included a transcript with two distinct consequence terms.
- **User supplied second annotation output:** A SnpEff `ANN` VCF row can be compared against every transcript in a preserved Ensembl record. Exact transcript ID and consequence term sets must all match for `agree`; incomplete coverage is `unresolved`. The app preserves the VCF and its computed hash, but does not run SnpEff or authenticate the user's version or database-hash assertion.
- **Portable replay check:** Bundle import verifies stored response hashes and recomputes the investigation result with the current engine. Older records export as a current replay with a new input ID. A bundle's internal hashes are corruption checks, not signatures or evidence of who supplied the data.

These behaviors are covered by unit, API, and local browser tests. The two public examples were checked live against Ensembl and NCBI in earlier development; no new live upstream result is claimed for this working tree. The causal comparison engine has **not** been validated against an independently controlled annotation engine. NCBI agreement verifies a narrow allele representation, not VEP's transcript predictions.

## Experimental or unsupported

- Insertions/deletions, including repeat shifting, remain unresolved even when local edited sequences match. Flank trimming does not implement VCF left alignment, HGVS 3′ shifting, SPDI contextualization, or VRS normalization.
- Assembly changes and different sequence accessions are unresolved; there is no liftover or sequence equivalence service.
- User supplied reference contexts, transcript consequences, and synthetic lookup entries are not independently verified. The fixture uses fabricated gene and transcript names. Only the explicitly checked public adapter records have an independent NCBI one-base observation.
- Different source releases produce a possible release-associated explanation, never a claim about the underlying evidence change.
- The current Ensembl endpoint does not supply a historical snapshot. Release metadata is read close to the VEP request, but the four calls are not atomic and VEP tool version is not reported. A fetched record must not be represented as an older analysis or a verified explanation of a historical discrepancy.
- No ClinVar integration, historical reconstruction, clinical review-status inference, patient-specific interpretation, or pathogenicity prediction exists.
- The NCBI check is restricted to primary nuclear GRCh38.p14 chromosomes and single nucleotide substitutions. Mitochondrial HGVS is outside its scope. It does not perform repeat-aware indel normalization, general HGVS conversion, VRS computation, or cross-assembly liftover. A different assembly patch accession is rejected until its mapping is independently pinned. A reference disagreement is preserved and SPDI/HGVS requests are skipped.
- Regression tests do not run VEP, ClinVar, or another external pipeline. Candidate snapshots must be supplied by the user; their provenance and content are not independently authenticated.
- The SnpEff check does not authenticate software execution, release, transcript database, or database SHA-256. Comparing two outputs can locate agreement or disagreement, but cannot prove why a consequence changed.
- A linked NCBI check summary never raises a transcript-selection finding to `verified`. A disagreement instead downgrades cross-source identity to `unresolved` and adds a reference-disagreement finding. A generic user-submitted investigation can include arbitrary provenance and check metadata; the comparison engine checks internal consistency but does not authenticate it against NCBI. Only source-generated comparisons link a locally preserved NCBI response.
- A file hash in user submitted `Provenance` is accepted as metadata but is not checked against a file. For adapter-generated snapshots, `Provenance.input_sha256` records the canonical VEP response hash. An investigation's top-level `input_sha256` is a hash of validated canonical JSON, not original input bytes.

## Failure modes to guard against next

False equivalence can arise if a supplied reference context is wrong. False causal certainty can arise if a controlled table is itself inaccurate or if hidden configuration variables differ. A current Ensembl response cannot reconstruct an old run. Future work needs independent public cases, stronger transcript matching, a versioned reference repository, and explicit historical source artifacts. Any regression-test feature must pin the reference, source, and tool versions it expects.

GenomeDebugger is a research and bioinformatics quality-assurance tool, not a certified clinical diagnostic device.
